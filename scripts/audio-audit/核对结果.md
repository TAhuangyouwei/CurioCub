## 生成方式核对

核对 Git 原始版本：`generate_audio.py` 使用微软 Xiaoxiao、正常语速，但把“长”的合成文本写成“长，长短的长”，把“了”写成“了，天黑了的了”。这些文本会把说明一起合成进单字文件。当前文本已缩回单个字，但多音字、轻声的实际合成仍未验证通过，不能视为解决。
原有其他单字及词语主要经 Edge TTS 的 Xiaoxiao 生成 MP3，存放在小程序资源中播放；补充字库的早期单字脚本还使用过公开拼音素材，词语使用 Xiaoxiao。当前播放代码按字卡的 characterAudioFile 取单字文件，练习页播放该字对应的副本。

原始第一批录音使用 Xiaoxiao、正常语速；暂存批次也是 Xiaoxiao，但语速为 -5%。最后一版“了”还额外用了 -20% 语境和 0.65 倍后期延时，听感不能据此认定与原有录音一致。

当前 Edge 接口不支持自定义 SSML，无法直接用音素指定 le 轻声。微软正式语音服务支持同一声音及中文 SAPI 拼音声调指定。
直接合成的请求已准备在 `scripts/audio-sources/le-direct.ssml` 与 `chang-direct.ssml`，不做语境截取和后期变速。尚未连接正式语音服务，尚未生成或验证效果。

用户目前没有 Azure 语音服务。已准备 `scripts/synthesize_hanzi_ssml_probe.py`，只在本地配置连接后生成“了、长”两份试听，不覆盖正式资源。缺失配置及请求内容的模拟检查通过，真实合成尚未执行。
另试了正常语速、不经处理的“嘞”单字替代，但“嘞”有 lei/le 读音歧义，本地音素词典标为 lei5，不能作为已确认的 le5 素材，已标记弃用。
